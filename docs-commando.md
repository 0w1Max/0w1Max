# 0w1Max Commando Activity — генератор SVG, версия 2 (Draft PR)

Анимированная 8-битная сцена **внутри GitHub README** по принципу Pac-Man Contribution Graph. Программа рассчитывает движения, попадания и расположение объектов, после чего сохраняет **самодостаточный SVG** без JavaScript и без внешней телеметрии.

## Поведение v2.1 — случайный доступный выбор

- Вместо проходов по рядам — **детерминированный случайный** выбор цели из доступных «фронтов» столбцов, с мягким приоритетом ближайших целей.
- Выстрел блокируется, если в той же колонке ниже осталась целая клетка, либо геометрический луч встречает другую живую клетку раньше выбранной.
- Между выстрелами появляются самостоятельные короткие пробежки; сохраняются прыжки, препятствия и доступные платформы.
- `seed` уровня и календарь активности полностью воспроизводят порядок попаданий; внешняя случайность не используется.

## Механика

- Реальный календарь GitHub GraphQL: 53 недели × 7 дней. Каждый настоящий день отображается квадратом; **каждый день с ненулевой активностью** назначается отдельной целью, нулевые дни остаются тёмными.
- Солдат с синей повязкой выбирает случайные достижимые цели по всему полю и меняет направление во время патруля, прицеливается и стреляет в клетки. Пуля появляется в точке дула и летит в соответствующий квадрат по наклонной траектории; квадрат гаснет после фактического момента попадания.
- Уровень детерминированно генерируется по `seed`: от 1 до 3 препятствий, от 1 до 2 небольших платформ. Во время прохода боец прыгает через преграды, иногда подпрыгивает без них, запрыгивает на платформу, стреляет с неё и спрыгивает.
- Боец не должен проходить сквозь преграды в сегментах бега. В планировщике учитываются ширина спрайта, сторона движения и безопасные точки приземления.
- Цикл завершается только после попаданий по всем ненулевым клеткам; надпись `MISSION COMPLETE`, затем боец возвращается на старт без телепорта, а клетки последовательно восстанавливаются перед повтором. Количество выстрелов и длительность **зависят от числа contributions**, это не фиксированные 10 секунд.
- Графика бойца встроена как 16 векторных кадров на основе согласованного спрайт-листа; игровые объекты и фон — SVG-фигуры. Это не полноценная управляемая игра и не копия оригинальных ресурсов Contra.

## Структура

- `scripts/mission.mjs`: чистый планировщик уровня и поведения. `buildLevel(grid, username, seedOverride)` создаёт воспроизводимую карту, `createMission(grid, level)` создаёт события движения и все выстрелы.
- `scripts/generate.mjs`: GraphQL, валидация календаря, преобразование маршрута и выстрелов в SVG с SMIL-анимацией, сохранение файла.
- `assets/sprites.json.gz.b64`: 16 векторных спрайтов из выбранного ранее визуального набора.
- `fixtures/demo-calendar.json.gz.b64`: только тестовые данные. Они явно маркируются `DEMO / TEST DATA`.
- `tests.mjs`: проверка полноты зачистки, направленных выстрелов, seed, платформ, прыжков, безопасности, негативных сценариев и обхода препятствий на 100 картах.

## Запуск и проверка

Node.js 22+; npm не требуется:

```text
node --test tests.mjs
node scripts/generate.mjs --demo --output generated/demo.svg
```

Настоящий календарь создаётся только при наличии `GITHUB_TOKEN` либо `GH_TOKEN`; `GITHUB_USER` задаёт пользователя. Токены не записываются в файл и не выводятся в логи. Ошибки API не превращаются в тестовые данные.

## Проверка через Draft PR

Workflow `.github/workflows/commando-activity-check.yml` работает с `contents: read`, генерирует `demo.svg` и `real.svg`, проверяет XML и публикует **только Actions artifact** `commando-svg-preview`. Загрузка в `main` или `output` при этом **не производится**.

В Actions открой успешный запуск PR → Artifacts → `commando-svg-preview`, распакуй ZIP и открой `real.svg` в браузере. Прямой просмотр локального файла поддерживается браузером, отображение именно на странице GitHub ещё нужно принять отдельно.

Workflow `.github/workflows/commando-activity.yml` предназначен для будущей публикации, но `if: vars.COMMANDO_ACTIVITY_PUBLISH == 'true'` не позволяет запускать её без отдельного изменения настройки. **Не сливать PR и не включать эту переменную до разрешения владельца.**

## Ограничения и критерии приёмки

- Не менять текущий профильный `README.md`, пока новый SVG не принят.
- Проверить тёмную/светлую тему, читабельность на мобильном размере, скорость воспроизведения, кадры прыжка и точное положение дула.
- Плотный календарь может потребовать более долгой анимации (несколько десятков секунд или больше), а файл SVG может достигать ~1 МБ; это следует оценить до публикации.
- Не выносить приватные репозитории и названия приватных проектов в результаты генерации.
- Не ставить сторонний Action из изменяемой ветки и не отправлять телеметрию на внешние серверы.

## v2.1 — этап 2: синхронизация ствола и эффектов

- Геометрия точки дула и вектор оси ствола определяются общей функцией `aimGeometry`; планировщик и SVG используют её без отдельной подгонки траектории.
- Верхняя часть позы `aim` поворачивается вокруг опорной точки, нижняя сохраняет положение; лицо персонажа зеркалится при повороте налево.
- Во время стрельбы **не используется** исходный спрайт `shoot-stand`, в котором уже нарисована вспышка. Вспышка отрисовывается один раз — непосредственно из дула, вместе с пулей в той же системе координат.
- Пуля целиком перемещается вдоль направления оружия и скрывается в момент попадания.
- Добавлены два повторно используемых пиксельных эффекта: повреждение без уничтожения и более выраженный взрыв при последнем попадании.
- `main` не изменён, работа только в Draft PR. Следующий этап: нормализация спрайтов и плавный финал.

## v2.1 — бесшовный повтор сцены

- Финал миссии фиксируется по завершении всех попаданий; надпись `MISSION COMPLETE` показывается после финального выстрела и исчезает до нового цикла.
- Боец продолжает движение после финала, возвращается на старт по обычным правилам столкновений и заканчивает в позе `idle`, лицом вправо.
- Убрано принудительное перепрыгивание координат на границе SVG-loop: начальное и конечное состояния совпадают конструктивно.
- Разрушенные клетки восстанавливаются волной по столбцам в течение возвращения бойца; яркость плавно нарастает за ~0,3 секунды.
- Регрессии проверяют финальный маршрут на разных seed, пустой календарь и корректную замкнутость.
- `main` и выпускной workflow не изменяются; проверочный workflow остаётся read-only.
