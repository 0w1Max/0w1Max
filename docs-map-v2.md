# Commando Activity — процедурные препятствия и платформы (v2.2)

## Правила карты

- Препятствия: **0–3**, платформы: **0–2**. Пустой уровень допустим.
- Выбор по воспроизводимому `seed`: та же активность GitHub и тот же seed дают ту же карту.
- Препятствия подбираются без повторения видов; если платформы две, они одинакового вида и ширины, но разные карты по `seed` могут использовать другие платформы.
- Доступные препятствия: `jungle-rock`, `fallen-log`, `sandbags`, `stone-ruin`, `tree-stump`, `supply-crate`.
- Доступные платформы: `wooden-bridge`, `mossy-stone`, `vine-ledge`, `metal-catwalk`, `camo-platform`.
- Отдельные слои: `scripts/mission.mjs` — количество, виды, размещение, валидация; `scripts/level-art.mjs` — оригинальные векторные 8-bit тайлы.
- Если безопасного свободного места не хватает, генератор **уменьшает** количество препятствий. Не ставит запасной ящик под платформой.
- Левый коридор зарезервирован для возврата бойца после `MISSION COMPLETE`.
- Платформы имеют высоту, доступную для прыжка с земли; прыжки, стрельба и сложность целей остаются неизменными.
- Никаких внешних ассетов и JS внутри итогового SVG.

## Контроль качества

Локально: `node --test tests.mjs`, `node scripts/generate.mjs --demo --output generated/demo.svg`. В GitHub Actions проверяются тот же тестовый календарь и настоящий календарь `0w1Max`.

Автотесты проверяют 1000 вариантов `seed` на допустимое число объектов, отсутствие повторов препятствий и различий между платформами на одной карте, перекрытий и доступность пустых карт. Отдельно проверяются маршруты полных миссий и отсутствие проходов сквозь препятствия.

## Визуальная приёмка

Открыть Draft PR #1: в его начале встроено анимированное SVG-поле с реальным календарём GitHub. Основной README и ветка `main` остаются без изменений. Обновление текущего предварительного SVG происходит только после успешного GitHub Actions.
## Локации v2.3

- Пять независимых 8-битных окружений: джунгли, пустынный каньон, снежная база, вулканическая зона, заброшенный завод.
- Локация выбирается по `seed` независимо от генерации препятствий и платформ; при одинаковом `seed` выбор воспроизводим.
- В GitHub Actions используется `GITHUB_RUN_ID`: новый запуск генерирует новую карту (повторения локаций случайно возможны). Для точного повторения можно установить `COMMANDO_MAP_SEED`.
- Цвета неба, силуэты, растительность и грунт зависят от локации. Высота земли остаётся 374, остальные игровые механики не меняются.
- Художественная сцена собирается в `scripts/locations.mjs` без внешних изображений или скриптов.

## Тематические комплекты локаций

Система `scripts/biomes.mjs` выбирает вместе с окружением допустимые платформы, препятствия и расцветку экипировки: джунгли — дерево и лианы, каньон — песчаник и деревянные мосты, снег — лёд и металл, вулкан — тёмные камни и горячие трещины, завод — металлические конструкции и разметка. Синяя повязка, кожа, оружие, размеры и анимации бойца сохраняются. Два объекта платформы на одной карте имеют один вид и одинаковую ширину, препятствий 0–3, платформ 0–2. Комплект выбирается по тому же воспроизводимому `seed`, что и карта. Публикация в `main` не выполняется.


## Детализированный пустынный каньон v3

- Для `desert` в итоговый SVG встраивается оригинальный пиксельный панорамный фон `assets/desert-canyon-background.png` (1200×430, палитровый PNG); файл включён в репозиторий.
- Генератор создаёт **самодостаточный SVG** с data URI без внешних сетевых ресурсов. Декоративный задник не содержит статических игровых платформ и ящиков; препятствия и платформы остаются отдельными объектами с проверяемой геометрией.
- Сохраняются механики HP, стрельбы, движения, бесшовного цикла; 0–3 препятствия, 0–2 платформы одного вида, тематическая экипировка бойца.
- Остальные четыре окружения не изменяются. Перед merge проверить отображение встроенного изображения в Markdown GitHub и на мобильных устройствах.
